## 10:10 至 10:30 修复 #57 + #56（Master 令「全修」；57b 策略联网调研后定案）

- **57b 策略定案（Master 要求「去网上找经验教训再选」）**：三条业界证据一致支持「标记界定所有权 + 无条件保留」，故未采纳「仅 checksum 匹配才保留」：① SilverModel 把 checksum（检测改动）与 User Code Blocks（保留用户代码）做成**两套互补机制**，生成时先取旧文件的用户块再合并；② cddl-codegen 原文「on regeneration the tool has no record of what it emitted last time, so it cannot tell 'I reworded my own comment' from 'the user wrote this'」——结论是**弃用「检测篡改」、改用显式标记**，契约 never silent；③ 完整性检测通识：hash 只能证明内容变没变，不能证明谁改的。
- **#57a 根因修正**：不是「机制局限」，而是**口径差 1 个换行**（写入侧 `join(lines)` vs 校验侧 `text[:cut]`），每次渲染必误判、与版本号无关。抽 `_script_zone_digest` 两侧共用，归一规则＝「尾部换行压成恰好 1 个」。**踩坑**：初版用 `rstrip` 剥光尾部换行，实测与旧记录值不等（09-15 报告 recorded 与 `head[:-1]` 相等，与 rstrip 版不等）；改「压成 1 个」后自然兼容历史报告。
- **#57b 落地**：`render_report` 只重写 checksum 标记之前，标记之后 AI 补充区无条件原样保留；真篡改时覆盖前自动备份到 `deliverables/.overwritten/`（never silent）；新增写入后回读自校验。
- **#56 落地**：`check_version_consistency` 三口径全比（frontmatter/标题/末条 Version），并修原实现误取**首条** Version 的隐患。**过程中抓到活体案例**：publish frontmatter 滞留 v3.20 而标题页脚已 v3.21，`title_and_footer` 口径照不到 → 补升 v3.22。
