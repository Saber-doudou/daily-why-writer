**决策 1 切不切 block → 推荐「切，但两阶段 + 先装 kill switch」**
- 依据：风控规则三阶段灰度「先观察→后告警→再拦截」，观察期≥72h 且**命中中合法流量
  占比 >5% 即判误杀风险**；**全量后仍需自动熔断回退**。
  本项目对照：① 观察期已满足 ✅；② 告警阶段 ❌；③ 小范围拦截 ❌（直接 100%）；④ 熔断回退 ❌
- kill switch 原则（Fowler）：**「若关掉它需一次新发布，这开关就失职了」**。
  现行 `--mode` 写在 prompt 里，改它要 `--update-automation` + 写库 + **次日生效** = 开关失职。
  → 推荐加 `DAILY_WHY_GATE_RELAX=1`（项目已有 `DAILY_WHY_DEDUP_RELAX=1` 同型先例）
- 建议 11-01 只切高置信子集（tertiary_only / banned_claim_hit / unknown_claim），
  unmapped_fact / unverified_mapping 继续 warn

**决策 2 转不转 C 方案 → 推荐「今天就转」**
- 依据：LLM-as-judge 可靠性剖面——**确定性校验(schema/正则)可靠性高成本极低；
  二元 pass/fail 中高；成对比较中高；LLM 连续打分(0-100)低至中**。
  本项目 v1 干的两件事（开放式 6 维连续打分 + 开放域事实判断）**恰好落在最低两格**。
  金句：「凡规则能解决的就用规则，把 LLM 留给剩下的」「评审被部署因它感觉全面，
  能活下来因**没人测量过它是否还诚实**」
