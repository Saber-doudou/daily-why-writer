## 详细判例

### CS-001: 话题重复（2026-05-19）

**话题**：肚子咕咕叫

**问题描述**：
- `topics_context.json` 仅含已注册话题，不包含 05-12 以后的新文章
- 选题时只查 topics 数组，导致"肚子咕咕叫"与 05-12 文章重复

**错误表现**：
```
选题："为什么肚子会咕咕叫？"
实际：2026-05-12 已发布同主题文章
```

**根因分析**：
- `prepare_topics.py` 只扫描 `topics_context.json` 中的 topics 数组
- 05-12 以后的新文章未注册到 topics 数组
- 选题逻辑依赖 topics 数组，未检查实际文件

**修正方案**：
1. 选题前 `grep -l "为什么" F:/WorkBuddy/daily-why/*.md` 搜索全部已有文章
2. 不能只查 topics 数组，必须检查实际文件
3. `prepare_topics.py` 已修复，新增方式5+6提取旧格式文章

**关联规则**：选题去重

### CS-002: 因果链错误（2026-05-29）

**话题**：指纹

**问题描述**：
- 描述生理机制时，因果链写反

**错误表现**：
```
原文："大脑还没学会脑补最后一帧画面"
实际：先有坠落感 → 触发惊跳反射（抖）
错误：写成"先抖 → 大脑误判为坠落"
```

**根因分析**：
- 通俗化描述时，忽略了事件发生的先后顺序
- 未反向检查因果链

**修正方案**：
1. 写完后反向检查因果链："如果 A 导致 B，那 A 必须先于 B"
2. 通俗化不能颠倒因果
3. SKILL.md 已新增规则："因果链必须写对"

**关联规则**：因果链必须写对

### CS-003: 逻辑矛盾（2026-06-02）

**话题**：指纹

**问题描述**：
- Q1 说"指纹不防滑"，Q2 又说"指纹排水抓稳"
- 读者困惑：到底防滑还是不防滑？

**错误表现**：
```
Q1: 指纹不防滑（在干燥条件下）
Q2: 指纹排水抓稳（在湿滑条件下）
问题：表面矛盾未搭桥，读者困惑
```

**根因分析**：
- 未在 Q1 或 Q2 中搭桥解释条件差异
- 读者不知道"不防滑"和"排水抓稳"适用于不同条件

**修正方案**：
1. 在 Q1 或 Q2 中搭桥："在干燥条件下不防滑 ≠ 在所有条件下不防滑"
2. 明确条件："干燥桌面 vs 湿滑表面"
3. SKILL.md 已新增规则："Q段之间的逻辑必须自洽"

**关联规则**：Q段逻辑必须自洽

### CS-008: 神经纤维功能绝对化（2026-06-04）

**话题**：伤口愈合发痒

**问题描述**：
- 将C纤维描述为"专门传递痒觉的细小神经"
- 四家AI中两家（DeepSeek、千问）明确指出

**错误表现**：
```
原文："C纤维是一类专门传递痒觉的细小神经"
实际：C纤维是无髓鞘、细直径的神经纤维，同时参与传递痛觉、温度和痒觉
问题：功能描述绝对化，忽略了多功能性
```

**根因分析**：
- 为了让读者容易理解，用了"专门"这个简化词
- 但"专门"暗示排他性，与事实不符

**修正方案**：
1. "专门传递痒觉" → "参与传递痛觉、温度和痒觉"或"多功能慢速信使"
2. 描述神经纤维功能时，检查是否有多重功能
3. 新增 FP-08 禁止模式

**关联规则**：FP-08 神经纤维功能绝对化

### CS-009: 跨系统类比不当（2026-06-04）

**话题**：伤口愈合发痒

**问题描述**：
- 将伤口发痒与过敏打喷嚏类比为"同一套系统"
- DeepSeek 指出：打喷嚏是三叉神经反射，和痒觉传导是不同通路

**错误表现**：
```
原文："本质上和过敏打喷嚏是同一套系统在工作"
实际：过敏打喷嚏（三叉神经反射）和伤口发痒（组胺→C纤维）传导通路不同
问题：仅凭表面症状相似就断言"同一套系统"
```

**根因分析**：
- 两者都涉及组胺，所以觉得是"同一套系统"
- 但组胺的下游通路完全不同：打喷嚏走三叉神经，发痒走C纤维
- "同一套系统"强调整个系统相同，过于绝对

**修正方案**：
1. "同一套系统" → "同一类化学语言"或"同一个信号分子"（只强调化学层面的共性）
2. 类比前检查信号通路是否一致
3. 新增 FP-09 禁止模式

**关联规则**：FP-09 跨系统类比不当

### CS-010: 机制遗漏+安全提示缺失（2026-06-04）

**话题**：伤口愈合发痒

**问题描述**：
1. 遗漏痂皮干燥收缩致痒机制（四家AI中三家指出）
2. 缺少"何时该就医"的安全提示（千问、豆包指出）
3. 未解释"从疼变痒"的体感变化（千问指出）

**错误表现**：
```
原文致痒机制：3条（组胺/神经再生/胶原沉积）
实际致痒机制：4条（+痂皮干燥收缩）
原文止痒方案：1种（冷敷）
实际应有方案：3种+（冷敷/保湿/减少摩擦）
原文安全提示：无
实际应有提示：痒感超2周或伴红肿渗液应就医
```

**根因分析**：
- 写作时聚焦于"微观机制"，忽略了"宏观物理因素"（干燥收缩）
- 止痒建议只想到最简单的方案，未系统思考
- 安全提示被认为"不是重点"而省略

**修正方案**：
1. 列举致病/致感机制时，考虑物理因素（干燥/收缩/牵拉）
2. 止痒/止痛建议至少提供2-3种方案
3. 安全提示用一句话点到即可，但不能省
4. 读者普遍有的体感变化必须解释

**关联规则**：读者体验优先（CHECKLIST §8）

### CS-011: 研究者引用不完整（2026-06-05）

**话题**：打哈欠

**问题描述**：
- 引用 Andrew Gallup 时只写"盖洛普做过实验"，未标注机构和发表期刊
- 引用胎儿哈欠研究时只写"超声波观察到"，未标注研究者 Nadja Reissland 和杜伦大学
- 四家AI均指出此问题

**错误表现**：
```
原文："盖洛普做过实验"
实际：Andrew C. Gallup, 纽约州立大学, 2011年 Evolutionary Psychology
问题：研究者引用不完整，读者无法溯源

原文："超声波观察到，大约孕中期起"
实际：Nadja Reissland 团队, 杜伦大学, 2012年 PLOS ONE, 4D超声波
问题：缺少研究者姓名、机构和发表期刊
```

**根因分析**：
- 为控制字数，省略了研究者出处
- 但读者和审稿AI都会要求可溯源性
- 首次引用研究者时完整标注是基本学术规范

**修正方案**：
1. 首次提及研究者时完整标注：机构+年份+发表期刊
2. 后续提及可省略出处
3. 新增 FP-12 禁止模式 + CHECKLIST §9

**关联规则**：FP-12 研究者引用不完整

### CS-012: 自动化未调用 Skill 工具（2026-07-07）

**话题**：猫呼噜声（通用型——所有每日冷知识文章）

**问题描述**：
- `automation-1778312519754` 的 prompt 中包含的是自然语言描述"加载 daily-why-writer skill"，而非 `Skill("daily-why-writer")` 工具调用指令
- 模型按描述执行了 A+C+F 规则（prompt 内联了规则副本），但从未触发 Skill 工具
- 导致 `usage-log.json` 中 daily-why-writer 和 daily-why-feed-learning 调用次数均为 0
- history-today 项目也存在相同问题但未暴露（其自动化使用 Read 实时加载规则文件）

**错误表现**：
```
usage-log.json 无 daily-why-writer 记录
→ 6 条记录均为系统元数据，无任何 writer/feed-learning 记录
→ daily-why-publish 因手动触发关键词调用而存在记录
问题：SKILL.md 的写作指导变更不传至自动化
（如新增的 FP-45 约束、§39 检查需通过 CHECKLIST/FORBIDDEN 间接生效）
```

**根因分析**：
- generate_prompt.py 生成的 automation prompt 中包含了完整的 A+C+F 规则内联副本
- 模型读到"加载 daily-why-writer skill"的自然语言描述后，直接使用内联规则而非调用 Skill 工具
- `Skill()` 是唯一能被 `usage-log` 追踪的工具调用方式，Read 不算
- 误以为"说了加载就会调用"，实际需要显式 `Skill("skill-name")` 指令

**修正方案**：
1. generate_prompt.py 的 generate_multi_agent_prompt() 阶段 1 最前面插入强制第 0 步：调用 Skill 工具，参数 skill=`daily-why-writer`，失败则回退 Read SKILL.md
2. Reviewer 阶段 FP 编号从硬编码改为逐条扫描文件
3. 验证通过后删除 prompt 内 A+C+F 内联副本，只保留编排壳
4. 已沉淀判例：CS-012

**关联规则**：自动化流程规范（跨技能）
