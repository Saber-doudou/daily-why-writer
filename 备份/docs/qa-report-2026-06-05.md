## Issues

### ISSUE-001: validate_article.py 对不存在/空文件返回 PASS

| Field | Value |
|-------|-------|
| **Severity** | critical |
| **Category** | functional |
| **Impact** | 自动化流程中文件缺失时不会被拦截，继续执行后续步骤 |

**Description:** `validate_file()` 捕获 FileNotFoundError 后调用 `result.error()`，该方法只向 `errors` 列表添加记录，不向 `p0` 列表添加。而 `print_report()` 和退出码逻辑仅检查 `has_passed_p0p1()`（只看 p0/p1 列表），导致报告显示 "✅ PASS" 且 exit code=0。

**Repro Steps:**

1. 运行 `python validate_article.py nonexistent-file.md`
2. **Observe:** 输出显示 "状态: ✅ PASS"，P0=0 P1=0，exit code=0
3. 运行 `python validate_article.py NUL`（空文件）
4. **Observe:** 同样显示 "✅ PASS"

**Expected:** 文件不存在或为空应显示 "❌ FAIL" 且 exit code=1

**Root Cause:** `validate_file()` line 335 用 `result.error()` 而非 `result.p0_error()` 处理文件缺失。报告和退出码逻辑未检查 `errors` 列表。

**Fix Suggestion:** 将 FileNotFoundError 和空文件的错误级别提升为 P0，或在 `has_passed_p0p1()` 中增加对 `errors` 列表的检查。

### ISSUE-002: prepare_topics.py --compact 写入错误的输出文件

| Field | Value |
|-------|-------|
| **Severity** | critical |
| **Category** | functional |
| **Impact** | 自动化工作流读取过期 compact 数据；完整版数据被覆盖 |

**Description:** `prepare_topics.py --compact` 的 `--output` 参数默认值始终为 `topics_context.json`，compact 模式只改变输出内容但不改变输出路径。导致：
1. `topics_context_compact.json` 不会被更新（当前过期：11:58 vs 14:55）
2. `topics_context.json` 的完整数据（含 category_stats、topics 详情）被 compact 数据覆盖

**Repro Steps:**

1. 运行 `python prepare_topics.py --compact`
2. 检查 `topics_context_compact.json` 的 `generated_at` 时间戳
3. **Observe:** 时间戳未更新（仍为旧值）
4. 检查 `topics_context.json` 的 keys
5. **Observe:** 只有 compact 字段（generated_at, total_count, topic_summaries），缺少 category_stats 和 topics

**Expected:** `--compact` 应写入 `topics_context_compact.json`，不影响 `topics_context.json`

**Automation Impact:** automation prompt 步骤1.1 运行 `prepare_topics.py --compact`，步骤1.2 读取 `topics_context_compact.json`。由于 compact 不更新 compact 文件，自动化始终读取过期话题列表。

**Fix Suggestion:** 当 `--compact` 且 `--output` 未显式指定时，自动将输出路径设为 `topics_context_compact.json`。

### ISSUE-003: orchestrator.py 状态逻辑矛盾

| Field | Value |
|-------|-------|
| **Severity** | critical |
| **Category** | functional |
| **Impact** | 状态追踪不可靠，断点续传逻辑可能错误判断 |

**Description:** 当前状态文件内容：
```json
{
  "date": "2026-06-05",
  "phase": "phase2",
  "phase1_status": "pending",
  "phase2_status": "completed"
}
```
phase1_status 为 "pending" 但 phase2_status 为 "completed"，违反了"阶段1完成后才进入阶段2"的设计原则。

**Root Cause:** orchestrator.py 的 `run_workflow()` 在文章已存在时直接调用 `run_phase2()`，但从未更新 `phase1_status`。代码 line 161-166:
```python
if self.check_article_exists():
    if phase is None or phase == "phase2":
        state = self.run_phase2(state)  # phase1_status 未更新
```

**Fix Suggestion:** 当跳过阶段1时，应自动将 `phase1_status` 设为 "skipped" 或 "completed"。

### ISSUE-004: validate_article.py 函数定义重复（shadowing）

| Field | Value |
|-------|-------|
| **Severity** | high |
| **Category** | functional |
| **Impact** | 维护风险，修改 format_checker 中的函数不会影响 validate_article.py |

**Description:** `validate_article.py` 在 line 26-30 从 `format_checker` 导入了 `count_chinese_chars` 和 `strip_markdown`，但又在 line 150-165 本地重新定义了同名函数，shadow 了导入版本。

验证结果确认两者是不同对象：
```
count_chinese_chars same? False
strip_markdown same? False
```

当前行为一致（结果相同），但如果未来只修改其中一个，将导致不一致。

**Fix Suggestion:** 删除 validate_article.py 中的本地定义（line 150-165），使用从 format_checker 导入的版本。
