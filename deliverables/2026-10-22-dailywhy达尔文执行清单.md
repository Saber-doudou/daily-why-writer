## 2. 前三轮详细步骤（第一优先，先把地基跑通）

### R1 P1-5 双文件 SSOT（0.5 人日）

**目标**：`topics_context.json` 与 `topics_context_compact.json` 永远一致，`check_topic` 与 L1 prompt 读同一份事实。

**改动文件**：`scripts/prepare_topics.py`、`scripts/check_topic.py`（只读路径对齐）。

**步骤**：
1. 备份 `config/topics_context.json` 与 `config/topics_context_compact.json`。
2. 改 `--compact` 分支：不再提前 return 只写 compact；改为同时写 full 与 compact，或只写 full、compact 由 full 派生。
3. 跑两次：`python scripts/prepare_topics.py`、`python scripts/prepare_topics.py --compact`。
4. 断言两个文件的 `topic_summaries` 完全一致，`generated_at` 一致。
5. 跑 `python scripts/full_selfcheck.py`，确认该项转绿。

**验收**：`full_selfcheck` 该项 ✅；两文件 `total_count` 与 `topic_summaries` 相等；`check_topic` 读到最新话题。

**回滚**：`git revert` 本轮 commit；用备份 json 覆盖。

---

### R2 P0-4 结构化契约（3 到 4 人日）

**目标**：4 个 JSON schema + 校验器；L2/L3 机器交接零正则。

**改动文件**：`contracts/evidence_card.schema.json`、`contracts/review.schema.json`、`contracts/learning_summary.schema.json`、`contracts/publish_manifest.schema.json`、`scripts/validate_contract.py`、L2/L3 读取逻辑。

**步骤**：
1. 先写 `review.schema.json` 与 `learning_summary.schema.json`，因为这两个历史事故最多。
2. 写 `validate_contract.py`：支持 `--schema`、`--file`，输出精确错误；失败退出码非 0。
3. 用 50 份历史文件回放：25 份 review、15 份学习总结、10 份发布清单；记录通过率与失败原因。
4. 改 L3：改进点、话题、字数全部从 JSON 读；Markdown 只作渲染。
5. 在提示词里加"只输出 JSON，不输出解释"；失败允许 1 次修复重试。

**验收**：历史文件通过率 ≥95%；L3 无正则提取；修复重试后失败率 <5%。

**回滚**：保留旧读取路径作为 feature flag；新路径失败即切回旧路径。

---

### R3 P0-1 证据卡 + 全阻断 + 日更兜底（3 到 4 人日）

**目标**：机制、数字、归因三类 claim 没来源就不许写；但当天一定有稿。

**改动文件**：`contracts/evidence_card.schema.json`、`scripts/evidence_gate.py`、`config/safe_topics.json`、自动化 prompt（S2/S3）。

**步骤**：
1. 写 `evidence_card.schema.json`：claim id、type、source_level、url、quote、verified_by、confidence。
2. 写 `evidence_gate.py`：四类检查（无 url/quote、tertiary 单独支撑、正文事实句无映射、映射到 unverified）。
3. 建 `safe_topics.json`：5 到 10 题，每题附现成证据卡；标注 `last_verified`、`used_date`。
4. 设计 4 级兜底：L1 删 claim → L2 定向补证 → L3 换角度 → L4 安全池；S2 硬上限 8 分钟。
5. 跑 3 条 test prompts：
   - happy path：完整证据卡，期望一次通过。
   - 证据不足：机制 claim 无来源，期望在 S2 阻断并走 L1/L2。
   - 对抗：白蚁稿类错误链，期望 `banned_claims` 命中，写作不使用。
6. 跑 10 例历史回放：白蚁、戴胜、僵尸蜗牛、雨滴带电、牛排、云有多重、蜂蜜、红酒挂杯等。
7. 日更演练：连续 5 天，每天故意给 1 个无来源题，确认都能在 8 分钟内兜底出稿。

**验收**：阻断正确率 100%；误杀 ≤10%；兜底成功率 100%；S2 ≤8 分钟；连续 5 天日更不中断。

**回滚**：gate 降为 warn（保留代码，不改 main）；恢复旧 prompt。

## 6. 禁止事项

- 不在 main 上直接改；所有改动走优化分支。
- 不同时改两个资产；一次只改一个，否则无法归因。
- 不跳过独立 Reviewer；主 agent 不自评。
- 不用 `git reset --hard`；回滚用 `git revert`。
- 不在未跑金集前合并；金集回退即停止。
- 不把安全池当常规选题；只在 L4 兜底用。
- 不把"阻断"做成"停更"；门禁只阻断 claim，必须走 4 级兜底。
- 不静默换题；走 L3/L4 必须在发布报告写明原因。
