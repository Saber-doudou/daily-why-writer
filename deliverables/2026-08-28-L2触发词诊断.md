### 1.2 工作区 MEMORY.md 简记（与权威源不一致）

⚠️ **漏记**：L2 实际有 5 个触发词，简记只写了 `dailywhy学习/投喂`，丢失了 `每日一个为什么学习`、`每日一个为什么学习总结`、`每日一个为什么投喂` 三个，尤其丢失了 `dailywhy学习总结` 这个被实际使用、且本次出问题的词。

### 1.3 三 Skill 触发词全集（暴露前缀冲突）

| Skill | SKILL.md 实际触发词 | MEMORY 简记 |
|-------|---------------------|-------------|
| L1 daily-why-writer | 每日一个为什么、每日一个为什么写作、**dailywhy**、dailywhy写作、每日冷知识 | dailywhy/每日冷知识 |
| L2 feed-learning | 每日一个为什么学习、每日一个为什么学习总结、每日一个为什么投喂、**dailywhy学习**、**dailywhy学习总结** | dailywhy学习/投喂 |

🔴 **前缀冲突（真实隐患）**：L1 的 `dailywhy` 是 L2 的 `dailywhy学习` / `dailywhy学习总结` 的**子串前缀**。当用户发送 `dailywhy学习总结` 时：
- 若匹配规则为「包含即触发」，`dailywhy` 也会命中该字符串 → L1 可能被误触发或双触发；
- 若匹配规则为「最长优先」，才能正确命中 L2。
无论哪种，当前定义都不收敛，依赖匹配器实现细节，属定义层缺陷。

## 三、失败归因：提示词有关？技能约束有关？

### 3.1 与提示词（AI 行为层）的关系 —— ✅ 强相关
- 全局铁律（用户 MEMORY.md）明确写：「已知触发词直接执行不追问、批量操作前 Master 确认」。
- 但 08-25 对话里 AI 把 `dailywhy学习总结` 当成了「软信号/确认意图」，只 ack 未 load skill 执行。这违反「已知触发词直接执行」铁律。
- **性质**：理解失败（把执行指令误读为状态确认）+ 操作失败（未 dispatch skill）。根子在 AI 端提示词/行为指令没有把「识别到 L2 触发词 = 必须加载 daily-why-feed-learning 跑全流程」写死。

### 3.2 与技能约束（定义层）的关系 —— 🟡 部分相关
- L2 SKILL.md 有硬前置：`Phase 0` 要求投喂素材文件夹存在且有效 AI ≥ 2（第 49-63 行）。L1 刚跑完、还没投喂时触发 L2，Phase 0 必然因「素材不足」终止。AI 据此停在「等投喂」是**符合技能约束的合理行为**，但表现为「未执行」。
- 技能缺陷：没有定义「被触发时若前置不满足应如何引导」（缺哪几个 AI 素材、去哪投喂），导致观感是「静默 ack」而非「明确卡在可恢复等待点」。

### 3.3 与触发词定义的关系 —— 🔴 是真实 bug
- 两套触发词记录不一致（SKILL.md 5 个 vs MEMORY 2 个）——查触发词时信息源打架。
- L1/L2 前缀冲突（`dailywhy` 是 `dailywhy学习` 子串）——匹配依赖实现细节，脆弱。
