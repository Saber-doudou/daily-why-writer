# 规则升降级机制设计方案

> 日期：2026-08-26 | 状态：待确认
> 核心目标：**越用越好 + 技能文件不膨胀**

---

## 一、设计原则（依据 Master 判断修正）

1. **规则零触发 ≠ 无用** — 恰恰相反，很多规则"写了规范所以没出事"，是预防有效
2. **规则 ≠ 教训** — 教训是记录（归档不影响行为），规则是行为约束（移走 AI 就不执行）。所以规则层**不能照搬**教训层的"归档删除"逻辑
3. **升降级的本质** = 调整加载优先级 + 标注状态，不是删除

---

## 二、规则三态状态机

| 状态 | 定义 | 加载优先级 | 动作 |
|------|------|-----------|------|
| 🔥 **活跃** | 近30天被教训引用（还在出事） | 必查 | 保留，必要时强化案例 |
| 🛡️ **预防有效** | 有原始教训 + 近30天零触发 | 按需 | 保留，标注状态 |
| 🔬 **待验证** | 从未被教训引用过 | 按需 | 保留，标注状态 |

**关键**：三种状态全部保留在文档中，只是分区摆放 + 打标签。

---

## 三、文件结构（FORBIDDEN.md / CHECKLIST.md 内部分区）

```
FORBIDDEN.md
├── ## 🟢 活跃区（写后自检必查）     ← 仅 ACTIVE 规则
│     FP-17 术语未通俗化 [活跃]
│     FP-14 研究来源归属 [活跃]
│     ...
├── ## 🛡️ 预防区（预防有效，按需查阅） ← PREVENT 规则
│     FP-04 机构名虚构 [预防有效 06-02]
│     ...
└── ## 🔬 待验证区（新规则，手动查阅）  ← NEW 规则
      FP-62 密度变化误用 [待验证 07-29]
      ...
```

CHECKLIST.md 同理。

**效果**：
- AI 写后自检时**只扫活跃区**（量小、聚焦真正在犯的问题）
- 预防区/待验证区规则不丢失（全部保留），但不再强制逐条检查
- 新增规则先进活跃区 → 稳定后自动降级到预防区 → 文档体积受控

---

## 四、自动化流程（越用越好闭环）

```
L2 投喂学习（每日）
   ↓ 学习完成后
自动运行 rule_lifecycle.py --update
   ↓
① 读 FEEDBACK_LOG（近30天引用）→ 标记 ACTIVE
② 读 FEEDBACK_ARCHIVE（历史引用）→ 标记 PREVENT / NEW
③ 重写 FORBIDDEN/CHECKLIST 分区头标记
   ↓
高频再犯规则 → 自动升级（标注"再犯N次"，AI 下次更重视）
低频预防规则 → 自动降级（移入预防区，减少检查负担）
   ↓
技能文件 ← 始终保留全部规则，只是分区更优
```

---

## 五、文件体积控制（不膨胀）

| 措施 | 说明 |
|------|------|
| 活跃区上限 | 建议 30 条以内（超出则最旧的降级到预防区） |
| 预防区不增长 | 预防区规则只在"再犯"时回到活跃区 |
| 案例精简 | 已验证有效的规则，可精简反面案例（保留标题+核心禁令） |
| 编号连续 | 新 FP/§ 顺序编号，不留空洞 |
