## 3. 问题与异常清单

### 🔴 P0-1（新增 #38）：git 推送静默失效，今日 commit 未上远端

**现象**：本地 HEAD=`bcc6dca`（09-07 11:42 提交），远端真实 HEAD=`3cb3e1f`（09-05 13:09）。**今日规则更新 + 素材池更新全部未推送**。

**根因（已实证）**：

```
$ git rev-parse origin/main
fatal: ambiguous argument 'origin/main': unknown revision or path not in the working tree.
$ git status -sb
## main...origin/main [gone]
$ git rev-list --count origin/main..HEAD
fatal: ambiguous argument 'origin/main..HEAD'   # stdout 为空
```

`l3_publish.py` 第 847 至 858 行的判定逻辑：

```python
ahead = subprocess.run(["git","rev-list","--count","origin/main..HEAD"],
                       cwd=str(repo), capture_output=True, text=True)
ahead_n = int((ahead.stdout or "").strip() or 0)   # 命令报错 → stdout="" → ahead_n=0
if ahead_n > 0:
    ...补推...
res.skip(3, "无新变更，跳过")     # ← 走到这里
```

1. `origin/main` 远端跟踪引用已 **`[gone]`**（`.git/packed-refs` 无 origin 条目，`.git/refs/remotes/origin/` 为空目录）；
2. 命令报错信息进 **stderr**，而脚本只取 `stdout` 且**不检查 returncode** → 异常被静默吞掉；
3. `ahead_n=0` → 判定「无新变更，跳过」→ **永远推不上去**。

**为何未被发现**：脚本**有**权威校验 `verify_remote_sync()`（第 218 行用 `git ls-remote origin refs/heads/main`），但它只在 `report_git_result()` 里调用，而 `report_git_result()` **只在推送成功之后**才执行。判定「要不要推」的阶段仍用本地 `origin/main`。

**违反已立铁律**：项目 MEMORY.md 明确「git 判定：权威 = `git ls-remote origin HEAD`；禁看本地 ahead 判推送；`[gone]` 即 mkdir loose ref 强写」。`phase3_git()` 用的正是被明令禁止的本地 ahead 判定，且**无 `[gone]` 兜底分支**。

**次生危害（决策链污染）**：`.workbuddy/memory/2026-09-07.md` 第 9、15 行直接记下「GitHub：no_rule_changes」「GitHub：无变更，跳过」—— AI 把脚本的跳过提示**当作事实写进记忆**。后续任何 AI 读到这行都会认为「今日无 git 变更，正常」，**与常驻缺陷 33「429 失败不进 memory」是同一类失效的不同变体**。

**关联线索（12:00 的 git 凭证修复）**：`.workbuddy/memory/2026-09-07.md` 记录 12:00 修复了「切换模型后两次弹出 CredentialHelperSelector 窗口」——根因是全局残留 `credential.helperselector.selected=manager` 与脚本 `-c credential.helper=wincred` 冲突。**这次弹窗冲突很可能正是 push 中断 → `origin/main` 变 `[gone]` 的直接诱因**，而凭证修复发生时脚本早已跑完，无人回头重推。

**影响范围**：
- 今日 `bcc6dca`（CHECKLIST 三区重写、FEEDBACK_ARCHIVE +5、topic_candidates +3、version.json）未上远端；
- 这不是偶发：`[gone]` 是持续状态，**今后每天的 commit 都会累积卡住**，而日志只会显示「无新变更，跳过」这种看似正常的信息；
- `automation memory.md` 末尾只有两行 IMA note_id、**无 `GitHub: commit bcc6dca` 行**，与 DB 状态互相印证。

**验证命令**：
```bash
cd /f/WorkBuddy/daily-why-writer && git ls-remote origin HEAD && git rev-parse HEAD
```

**修复方向**：把 Phase 3 的推送判定从「本地 `origin/main..HEAD`」改为「`git ls-remote origin refs/heads/main` 与本地 HEAD 比对」；`[gone]` 时按铁律强写 loose ref；命令 returncode 非零必须告警而非静默。
