# L2 全流程失败根因诊断与修复方案（终版）

> 诊断对象：`dailywhy学习总结` 触发词在切换 hy3 大模型后导致 L2（四AI投喂学习）全流程失效
> 诊断日期：2026-08-28 ｜ 诊断者：SeniorDeveloper（独立诊断，非 hy3 自查复核）
> 证据基础：SKILL.md 三件套（L1/L2/L3）、工作区 MEMORY.md、磁盘产物实态核查、conversation_search 历史对话检索

---

## 〇、结论速览（TL;DR）

1. **「触发词失效」不成立**：`dailywhy学习总结` 在 L2 SKILL.md 中合法存在，且 08-21、08-25、08-28 三天均留下了**完整六阶段产物**（素材 + 学习总结.md），L2 全流程最终都完成了。
2. **真实问题是「触发到执行」链路脆弱**：换模型后，AI 对触发词的响应从 deepseek 的「触发即执行」退化为 hy3 的「ack 确认 + 挂 To-do 待办」，当次对话未立即启动 L2。这与 hy3 自查报告的**核心论断（只 ack 未执行）在历史事实层面部分冲突**。
3. **根因是三层叠加**：定义层真实 bug（L1 裸 `dailywhy` 子串前缀冲突 + 触发词双记录不一致 + 「学习总结」双义 + L2 缺阶段0守卫）、执行层模型行为差异（deepseek 指令执行型 vs hy3 对话确认型）、架构层无确定性路由（无机械兜底、无冒烟测试）。
4. **hy3 自查报告的价值**：触发词合法性、MEMORY 简记漏记、前缀冲突三项判断正确；但「08-21/08-25 未执行」的论断**证据链断裂**（基于 summary 时间快照，未核对磁盘产物），且漏掉了最根本的「模型切换导致行为模式变化」这一归因。
5. **修复优先级**：P0 三个动作（L2 加阶段0守卫、消除前缀冲突、单一权威源对齐）即可让 hy3 下触发成功率趋近 100%；P1/P2 为机制加固与达尔文式自进化。

```
用户输入「dailywhy学习总结」

   ├─ L2 SKILL.md 无「阶段0 守卫」→ 无强制加载锚点（对比 L1 有「✅ SOP已加载」守卫）
```

## 三、根因分析

### 3.1 定义层：真实 bug，与模型无关（换任何模型都会踩）

| # | 缺陷 | 证据 | 危害 |
|---|------|------|------|
| D1 | **L1 裸词前缀冲突**：L1 触发词含 `dailywhy`，是 L2 `dailywhy学习`、`dailywhy学习总结` 的子串前缀 | L1 SKILL.md 第 7 行「dailywhy」；L2 SKILL.md 第 6 行「dailywhy学习」 | 路由歧义：包含匹配时 L1/L2 双命中，匹配结果依赖实现细节 |
| D2 | **触发词双记录不一致**：SKILL.md 声明 5 个词，工作区 MEMORY.md 简记仅 2 个（丢 `dailywhy学习总结` 等 3 词） | MEMORY.md 第 11 行 vs L2 SKILL.md 第 6 行 | 查证时信息源打架，AI 对「是否合法触发词」产生自我怀疑 |
| D3 | **「学习总结」双义**：既是 L2 触发词，又是日常高频对话词（「帮我总结一下」） | 语义分析 | 意图消解依赖模型能力，弱模型易解读为名词短语 |
| D4 | **L2 缺阶段0 守卫**：L1 有「显式输出 ✅ SOP已加载 方可写作」强制守卫，L2 没有对等机制 | L1 自动化 prompt 阶段0 vs L2 SKILL.md 全文 | 无强制加载锚点，AI 可「识别触发词但不加载 skill」而不违反任何显式规则 |

### 3.2 执行层：模型行为差异（本次失败的触发因素）

- deepseek 行为模式：内化了全局铁律「已知触发词直接执行不追问」，见触发词 = 执行指令，直接 load skill。
- hy3 行为模式：倾向对话式助手风格，把触发词当作「软信号」——acknowledge、记录 To-do、等待进一步指令；对多义词偏向「对话任务」解读而非「技能路由」。
- 依据：用户长期记忆记录 hy3 在诊断推理上存在「先猜后证」软肋（2026-07-08 观察）；本次 08-21 对话 summary 实证「acknowledged trigger phrase to enter L2 flow」+「To-dos: Continue L2 four-AI feeding learning flow」。

### 3.3 架构层：无确定性路由（系统性缺口）

- skill 路由完全依赖模型从 available_skills 的 description 做语义匹配，无机械层兜底。
- 无触发词路由表（输入模式 → skill + 动作 的确定映射）。
- 无模型切换后的冒烟测试机制（换模型 = 静默改变全部路由行为，无预警）。
- 同族对照：`history-today-feed-learning` 使用结构化 `trigger_words:` YAML 字段，比 daily-why 系列的 description 内嵌文本更利于机械解析——说明这是 daily-why 系列的结构性缺陷，而非平台限制。

### 3.4 根因一句话

> **换模型放大了定义层的结构性缺陷**：`dailywhy学习总结` 这条触发链路本身存在前缀冲突、双记录、双义、无守卫四个隐患，deepseek 靠「触发即执行」的行为习惯掩盖了它们；hy3 没有这个习惯，隐患全部暴露，导致触发后停在「ack 确认」而非「执行」。

## 六、修复与优化方案（P0 到 P2）
