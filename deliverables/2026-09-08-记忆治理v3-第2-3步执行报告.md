## 二、第 3 步：衰减评分（`memory_decay.py` v1.0 新建）

### 实现

| 能力 | 说明 |
|---|---|
| 状态判定 | **10 天未触发 → 待降级**（常驻 → 索引行）；**20 天 → 待下沉**（主文件删行，仅留指针） |
| pin 豁免 | 低频高代价规则永不降级，只保持 |
| Refresh-on-Read | `--touch §NN` 记录被引用，`access_count +1`、重置计时 |
| **再犯即升** ⭐ | `--boost §NN` 计数 +5 并重置计时，立即升回最高 |
| 衰减评分 | `0.3×recency + 0.3×access_freq + 0.2×freshness + 0.2×type_weight`，用于排序参考 |
| 安全 | 任何改写前自动 `.bak-时间戳` 快照；默认只读报告 |

### ⚠️ 修掉一个真实 bug：pin 豁免曾完全失效

首跑时 5 条 pin 条目的 `owner` 显示 `unknown`。根因：我在分片里写的是 `**pin: true**`（加了粗），而正则按 `pin:` 匹配，导致整条元数据解析失败 → **pin 被当作 false**。

后果很隐蔽：今天所有条目都是活跃的，看不出问题；**但 20 天后这 5 条低频高代价规则（git 判定、同步清单、L3 Phase 时序、版本号易腐、同文件多处编辑）会被误判下沉**。

已修（正则容忍 `**` 与行尾说明），复跑确认 5 条 pin 全部正确识别。

**这个 bug 是跑真实数据才暴露的，构造样本测不出来**——又一次印证 EXP-014「实测优于推演」。
