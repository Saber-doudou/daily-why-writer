## 4. 未完成与原因（阻塞在 L1 接线）

1. **3 条测试提示词未实跑**：它们要跑的是 L1 全链路（选题 → 证据卡 → 门禁 → 写作 → 审校），而 L1 的执行载体是平台自动化 + `generate_prompt.py` 生成的 prompt。改 prompt 属于生产变更，必须与 R2 合并批次一起走，否则影子区跑出来的不是生产行为。
2. **5 次模拟 L1 运行未做**（裁决书 C4）：同上，且每次要真跑一次写稿，成本与污染都不小；建议在合并后、用 `--dry-run` 的 L3 配合，在真实日期上观察。
3. **S2 本地计时未接**（裁决书 C5）：S2 是 L1 内部的写作阶段，脚本侧拿不到它的起止时间。要么在 `generate_prompt.py` 里让 Orchestrator 落一个 `time.monotonic()` 打点文件，要么等 R4 的 `run_metrics`。两种都需要改生产侧文件。
4. **门禁尚未接进 L1/L3 主链路**：当前只有独立 CLI，没有任何生产路径调用它。

结论：R3 的「工具」已经可用且自证，「接线」必须和 R2 一起在合并批次里做，不能在影子区单独宣布收口。
