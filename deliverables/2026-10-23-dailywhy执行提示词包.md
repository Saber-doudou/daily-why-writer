# dailywhy 执行提示词包（交接用）

> 版本：v1.0
> 日期：2026-10-23
> 用途：Master 把对应提示词直接发给执行人（或其 AI 会话），不需要转述上下文
> 配套文档：
> - `deliverables/dailywhy-优化交接包-20261022/README.md`
> - `deliverables/2026-10-21-dailywhy优化方案书.md`（v1.3）
> - `deliverables/2026-10-22-dailywhy达尔文执行清单.md`（v1.1）

---

## 使用说明

| 场景 | 用哪一段 | 怎么用 |
|---|---|---|
| 第一次开工 | 提示词 1（启动） | 整段复制给执行人的 AI 会话；只做 R1 |
| R1 已填好版 | 提示词 1A | 不想改占位符就直接用这段 |
| 每一轮开工 | 提示词 2（单轮模板） | 把 `{ROUND}`、`{ASSET}`、`{GOAL}`、`{ACCEPTANCE}`、`{ROLLBACK}` 填掉 |
| 每轮审校 | 提示词 3（独立审校） | 发给执行人 spawn 的 Reviewer 子 agent，不要让执行人自己评 |
| 每轮汇报 | 提示词 4（验收汇报） | 让执行人按这个格式交 1 页记录 |
| 出错/回退 | 提示词 5（异常回滚） | 出现回归、测试失败、日更中断时立即用 |
| 每周收口 | 提示词 6（每周汇总） | 每周五发给执行人 |
| 一次性全做 R1 到 R13 | 单独文件 `2026-10-23-dailywhy一次性全做提示词.md` | 用总控提示词；执行人自己分开做、分开审校，不逐轮等确认 |

**三条总规则，所有提示词都适用：**

1. 一次只改一个资产；不做与当前轮次无关的重构。
2. 不碰 main、不碰 09:40 的 L1 自动化 prompt、不提交 `scripts/config.json`。
3. 没有跑过的命令，不许写“已通过”；独立审校没过，不许写 keep。

**如果执行环境没有子 agent 能力**：用另一个独立会话（新上下文）做审校，或让第二个人复核；仍然禁止执行人自评。审校结论必须带命令与输出证据。

```text
- C:/Users/admin/.workbuddy/binaries/python/versions/3.13.12/python.exe scripts/full_selfcheck.py

不要自动进入 R2。任何回滚、异常、基线不符，立即停止并报告。

【硬约束】
- 不改 main；不直接改 09:40 的 L1 自动化 prompt；不提交 scripts/config.json。
- 一次只改一个资产；不用 git reset --hard；回滚用 git revert。
- 不伪造命令输出；没有跑过的命令不写“已通过”。
- 不做与 R1 无关的重构、格式化、规则修改。
```

```text
{ROLLBACK}
```

## 提示词 3：独立审校（发给 Reviewer 子 agent）

```text
你是独立审校员，只读，不修改任何文件。你的任务是判断本轮改动应该 keep 还是 revert。

【输入】
- 轮次：{ROUND}
- 资产：{ASSET}
- 目标：{GOAL}
- 改动 diff：{DIFF}
- 执行人跑过的命令与输出：{OUTPUTS}
- 验收口径：{ACCEPTANCE}

【你要做四件事】
1. 读方案书第 10 节与执行清单 {ROUND} 段，确认验收口径没有被执行人改写。
2. 检查 diff：
   - 是否只改了一个资产？
   - 有没有无关改动、格式化噪音、顺手重构？
   - 有没有吞异常、静默失败、硬编码路径、伪造输出？
3. 亲自跑验收命令，不要相信执行人的转述：
   - full_selfcheck.py
   - 本轮相关脚本
   - 金集冒烟（如果已有）
4. 输出结论，必须带证据：
   - verdict：keep / revert
   - 证据：命令、真实输出、关键行号
   - 风险：遗漏、回归、对日更的影响
   - 若 revert：给最小修复建议，不要替执行人写代码

【硬约束】
- 不修改任何文件；不替执行人补代码。
- 不用“看起来没问题”代替证据；没有跑过的命令不写“通过”。
- 如果验收命令因环境失败，标“未验证”，不要判 keep。
```

## 提示词 5：异常与回滚

```text
本轮出现异常。立即按下面顺序处理，不要继续“再改一版看看”：

1. 停止改动，保持现场。
2. 保存证据：
   - git diff
   - 完整命令与报错
   - 相关日志行（l3_run.log / 脚本输出）
3. 如果已经 commit，执行 git revert HEAD；禁止 git reset --hard。
4. 在 results.tsv 记一行 revert，note 写根因，不写“环境问题”这种空话。
5. 输出异常报告：
   - 现象：
   - 根因（证据支撑）：
   - 已回滚到什么状态：
   - 下一次只改哪一个假设：
   - 是否需要 Master 决策：

如果同一轮连续失败 2 次，停止该轮，不再尝试；等 Master 决定是否换方案。
```
