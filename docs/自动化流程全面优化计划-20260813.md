## 2. 对上一版改造方案的审视结论

### 2.1 认可（方向正确，继续采用）

1. 取消 spawn、主代理同步审校——与 Darwin 复评发现的"边界黑洞"结论一致（详见 3.3）。
2. 强调先改 `generate_prompt.py` 源码再 `--update-automation`——顺序正确，防覆盖。
3. 复用现成脚本（validate/auto_fix/orchestrator）——符合 Lean 消除浪费原则。
4. 保留人工对照 CHECKLIST/FORBIDDEN——08-13 实证其不可替代。

### 2.2 四个缺口（本计划补齐）

| 缺口              | 说明                                                                       | 对应优化                                  |
| --------------- | ------------------------------------------------------------------------ | ------------------------------------- |
| **只见 L1 不见全链路** | 方案只改阶段2；但今天第 1 次卡（选题失败）和第 4 阶段（投喂）问题没覆盖                                  | 本计划 Phase 1 补话题池、上报路径；Phase 3 补 L2/L3 |
| **没解决"双架构并存"**  | 方案改 SKILL.md 多 Agent 段，但单 Agent 工作流段落（Phase 0 到 4）仍与多 Agent 段重复，两个源头继续漂移 | Phase 1 统一为单一权威工作流                    |
| **无量化验收**       | 方案有验证清单但无 KPI 目标值                                                        | 本计划第 5 节给量化目标                         |
| **未评估"检查点"缺口**  | 自动化场景无告警/上报机制（Darwin 维度 4 短板）                                            | Phase 1 加"选题失败/审校降级上报"规则              |

| 8 | 实测表现           |  25 | 8/10 | 同步自审实测可行（约 1 分钟）；spawn 实测不可靠；文档仍宣称 spawn 为默认           |

**总分 = (8×9 + 15×8 + 10×7 + 7×6 + 15×9 + 5×9 + 15×7 + 25×8) ÷ 10 = 78.9**

> 口径说明：06-12 基线 95 分评估的是"写作 skill 单 Agent 模式"；本次 78.9 分评估的是"写作 skill + 自动化执行链路整体"。分数差异主要来自执行链路暴露的架构问题（TP2/TP3 实测失败），**不代表写作规则质量退步**。

### 3.3 Darwin 的核心结论（三个结构性问题）

1. **边界黑洞**：维度 3 得分最低的风险点——SKILL.md 异常表写了"空返回→重试→跳过"，但 spawn 是阻塞调用，规则无法打断工具等待。**任何依赖"spawn + 回传"的写法都是结构性缺陷，必须从架构上移除依赖**（与上一版方案结论互相印证）。
2. **检查点缺失**：维度 4——自动化场景没有"失败上报"检查点。选题失败、审校降级都应显式上报，而不是静默终止。
3. **双架构并存**：维度 7——单 Agent 工作流与多 Agent 段是两个源头，规则漂移风险高（08-11 覆盖事故是后果之一）。优化方向是**统一为单一权威工作流，执行载体（prompt）与文档载体（SKILL.md）一对一同步**。

## 4. 全面优化计划（分阶段）

### Phase 0：快速止血（1 到 2 天）——同步化改造落地

> 内容即上一版方案的 6.1 到 6.4，此处不再重复，仅列执行顺序。

1. 改 `generate_prompt.py`：阶段2 替换为"同步式审校"模板（原第 214 到 231 行），阶段3 同步简化（原第 233 到 239 行）。
2. 运行 `generate_prompt.py --update-automation` 写库，并核对数据库 prompt 不含 spawn。
3. 改 SKILL.md 多 Agent 段 v1.0 → v1.1（同步审校口径）。
4. 全仓 grep `spawn|reviewer|独立审校` 确认无遗漏硬编码。

**验收**：下次自动化运行，阶段2 无 spawn，全流程小于 5 分钟，无 `Run timed out`。

### Phase 1：结构优化（本周）——消灭双架构 + 补检查点

| # | 动作                 | 细节                                                                                                                      | 对应 Darwin 维度 |
| - | ------------------ | ----------------------------------------------------------------------------------------------------------------------- | :----------: |
| 1 | **SKILL.md 工作流统一** | 以多 Agent 段（v1.1 同步审校）为唯一权威工作流，单 Agent 段（Phase 0 到 4）降级为"参考实现"或在 v1.2 合并；删除重复的 Phase 3 自检与多 Agent Phase 3.5 审校并存段        |    维度 2/7    |
| 2 | **选题失败上报**         | prompt 与 SKILL.md 加硬规则：3 轮判重终止前，必须输出"⚠️ 今日选题失败：候选 3 个 + 建议方向 3 个"，不得静默终止                                                |     维度 4     |
| 3 | **话题池扩容**          | 准备 15 到 20 个新话题方向（冷门生物/物理/生活现象），写进 `config/topics_context.json` 或独立候选池文件；评估 `check_topic.py` 相似度阈值是否过严（对比 08-13 三个误判案例） |    TP3 场景    |
| 4 | **审校降级标记**         | 阶段2 一旦走降级路径（无论原因），输出带"⚠️ 审校降级为主代理自审"标记，进工作日志                                                                            |     维度 3     |

### Phase 2：自动化增强（2 到 4 周）——减少人工依赖

| # | 动作             | 细节                                                                                                                | 预期收益                          |
| - | -------------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| 1 | **脚本规则扫描器**    | 新增 `scripts/rule_scanner.py`：把 CHECKLIST/FORBIDDEN 中可程序化判定的规则（破折号、拟人动词表、绝对化表述）固化为脚本检查项，作为 validate_article.py 的补充 | FP-25 类问题从"人工抓"变"脚本抓"，人工专注语义层 |
| 2 | **调度前移监测**     | 在 automation 运行开头记录 `scheduledAt vs 实际触发`，写入工作日志；连续 3 次前移超 5 分钟则提示升级 WorkBuddy 版本/反馈                              | 量化调度漂移，推动平台侧修复                |
| 3 | **审校超时硬控（可选）** | 若日后恢复 spawn，用"结果文件 + 轮询"替代消息回传（文件系统即通信通道），并设外部超时判定                                                                | 防阻塞复燃                         |

### Phase 3：持续改进（月度）——全链路健康

| # | 动作             | 细节                                                                                                                             |
| - | -------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 1 | **L2/L3 链路审查** | 用 Darwin 评估 daily-why-feed-learning 与 daily-why-publish（当前均为 pending，未评），重点：L2 投喂后的规则回流是否经过 generate_prompt.py 模板、L3 发布失败是否有上报 |
| 2 | **规则温控**       | 借鉴 history-today 的 rule_heat 机制：超过 30 天未触发的 CHECKLIST/FP 项进入休眠，降低上下文压力（当前 CHECKLIST 82 项 + FP 65 条膨胀中）                         |
| 3 | **月度 KPI 复盘**  | 每月 1 号按第 5 节指标复盘，产出简短报告归档 docs/                                                                                                |

## 6. 风险与回滚

| 风险              | 应对                                                       |

| 同步化后失去"独立视角"    | 规则扫描器（Phase 2）补程序化防线；人工对照保留                              |
