# Daily-Why 自动化 Reviewer 改造建议（同步式审校方案）

> ⚠️ **已废弃（2026-08-20）**：本文档的"同步式审校"方案已被 v4.1 撤销。08-20 实证 spawn 独立 Reviewer 可行（去掉 name 参数），审校机制已升级为 v2.0（独立 Reviewer 主路径 + 熔断链 + 文件检测）。本文仅作历史决策记录保留，勿按此执行。
> 编写时间：2026-08-13
> 适用对象：每日冷知识自动化 `automation-1778312519754`（L1 撰写 + 阶段2审校）
> 背景：2026-08-13 当日任务因 Reviewer 子 agent 空返回卡住约 2 小时，最终由主代理亲自审校兜底完成。本文档给出根治方案，供后续改造参考。

---

## 1. 问题现象

- 阶段2 使用 `Agent` 工具 spawn 独立审校子 agent（`general-purpose`，前台），要求其读取初稿 + 运行 `validate_article.py` + 加载 CHECKLIST/FORBIDDEN + 输出 JSON 审核报告。
- 子 agent **返回空结果**——没有任何 JSON 回传，主代理无法拿到 `pass / p0_count / p1_count / p2_count / score / issues`，阶段3（修复+输出）与阶段4（建投喂文件夹）被迫中断。
- 这不是文章质量问题：脚本 `validate_article.py` 对同一初稿给出 ✅ PASS（P0=0/P1=0/P2=0，100分）。

## 2. 根因分析

| 可能层 | 说明 |
| --- | --- |
| Agent 回传/子进程异常 | 本环境（08-06 已有先例 `No active team found`，08-13 再次出现空返回）下，spawn 出的独立 agent 在读取较大规范文件（CHECKLIST.md / FORBIDDEN.md）或运行校验脚本时内部出错，未能产出最终消息即退出。 |
| 异步回传不可靠 | 自动化任务依赖"子 agent 把 JSON 作为最终回复返回"，但该通道在多轮大上下文下不稳定，缺乏超时兜底之外的硬保障。 |
| 异常表未覆盖"空返回" | 原 SOP 异常处理表只写了"超时10分钟跳过"，未明确"返回内容为空/非 JSON"的判定与重试口径，导致主代理只能凭经验兜底。 |

**结论**：双 Agent 真审校的"独立进程 + 异步回传 JSON"在当前环境是脆弱点，应改为**主代理同步执行审校**，去掉对子 agent 回传的依赖。

---

## 3. 推荐方案：同步式脚本审校 + 主代理人工复核

核心思路——**取消 spawn Reviewer，改由主代理（Orchestrator）在同一轮同步完成全部审校动作**。审校本质就是"跑脚本 + 对照两本规范 + 结构校验"，这些主代理本来就有全部工具权限，不需要独立进程。

### 3.1 阶段2 新流程（替代 spawn）

1. 主代理用 `Read` 读取初稿全文。
2. 主代理用 `Bash` 运行：
   `python .../scripts/validate_article.py "{初稿路径}"`
   记录脚本的 P0/P1/P2 与得分。
3. 主代理用 `Read` 加载 `references/CHECKLIST.md` 与 `references/FORBIDDEN.md`，逐项人工扫描（FP 编号以文件实际内容为准，不写死）。
4. 主代理做**最小结构验证**：A段引用块（`>` 开头）、C段 Q 格式（`**Q1：/Q2：/Q3：**`）、F段含"冷知识反转"标签、结尾四列表格，任一缺失即 P0。
5. 主代理**就地输出审核报告**（Markdown 表格或 JSON 文本），判定 `pass = P0=0 且 P1≤2`。

### 3.2 关键收益

- 无异步回传 → 不会再卡流程。
- 主代理本就持有全部工具，无额外开销。
- 08-13 实测证明：主代理审校比脚本多抓出 FP-25（3处 `——` 破折号），人工复核价值不可替代。

### 3.3 保留"双 Agent"名义（可选）

若 Master 仍想保留"双 Agent"架构叙事，可改为**同步 spawn + 强制取返回值**：调用 `Agent` 时不依赖其"最终消息"，而是让子 agent 把报告 **写入一个临时文件**（如 `articles/2026-08/{日期}-reviewer-report.json`），主代理随后 `Read` 该文件。这样即便消息回传为空，文件落盘仍可兜底。但本环境子 agent 写文件也可能失败，故**首选 3.1 的纯同步方案**。

---

## 4. 具体落地步骤

### 4.1 改自动化 prompt（阶段2 整段替换）

将阶段2 的 spawn Reviewer 指令，替换为上面的 3.1 五步同步流程，并在末尾明确：

> "审校由主代理同步完成，不 spawn 独立子 agent。审核报告以 Markdown 表格输出，含 pass / P0 / P1 / P2 / score / issues（每项 level/category/description/suggestion）。通过条件：P0=0 且 P1≤2。"

### 4.2 改 SKILL.md（如阶段2定义写在 daily-why-writer 内）

定位 SKILL.md 中"独立审校"相关段落，把"spawn Reviewer"改为"主代理同步审校"，保留 CHECKLIST / FORBIDDEN / 最小结构验证的引用。

### 4.3 强化异常处理表

在原异常表新增一条：

> **子 agent 空返回 / 非 JSON 返回**：立即改由主代理同步审校（见 3.1），不得等待重试；记录"⚠️ 审校降级为主代理自审"标记，流程继续。

### 4.4 同步 generate_prompt.py 模板（重要）

若自动化 prompt 由 `scripts/generate_prompt.py --update-automation` 生成并写入数据库，**改完规则后必须同步修改该脚本模板源码**，否则下次 regenerate 会把改动覆盖掉（参考 2026-08-11 同类事故：硬约束只改库未改源码导致丢失）。

### 4.5 监控验证

- 下次自动化运行观察：是否还有子 agent 空返回日志。
- 确认阶段2 不再依赖 spawn，计时从"选题→输出"应稳定 < 5 分钟（08-13 主代理自审实测约 1 分钟）。

---

## 5. 风险与回滚

| 风险 | 应对 |
| --- | --- |
| 主代理自审可能遗漏子 agent 的"独立视角" | 保留 FORBIDDEN/CHECKLIST 强制加载步骤；日后可加一个纯脚本化的"规则扫描器"做第二道防线。 |
| 改造后若想恢复双 Agent | 保留本文档 3.3 的"文件落盘兜底"方案，按 4.1 反向改回即可。 |
| generate_prompt 覆盖 | 改源码模板（4.4），改完跑一次 `--update-automation` 验证数据库与源码一致。 |

---

## 6. 一句话总结

**把"spawn 独立 Reviewer 异步回传 JSON"改成"主代理同步跑脚本+人工对照规范"，是根治 08-13 卡死的最简、最稳路径；别忘了同步 `generate_prompt.py` 模板，否则会被下次 regenerate 覆盖。**
